# 独立主持人管理后台

玩家网站只负责入场、摇动计分和只读大屏。管理后台是单独的 Node 进程、端口和域名，打开后台直接创建比赛、开始比赛或开启下一局，无密码、无登录页。旧 `/host/:code` 地址跳转到只读大屏；旧房间主持凭证不再有管理权限。

## 配置

1. 将 `admin/env.example` 复制到项目根目录 `.env.admin`，填入随机服务密钥（至少 32 位）。不将配置文件提交 Git。
2. 游戏 Worker 的秘密绑定 `ADMIN_SERVICE_KEY` 必须与管理进程一致。本地开发放在根目录 `.dev.vars`；现有本地生产预览 `npm start` 使用的 Wrangler 配置位于 `dist/server/`，需在该目录提供 `.dev.vars`。正式 Worker 部署通过运行时秘密绑定配置。缺少绑定时管理接口返回 503，玩家已有房间的参赛和计分仍可用。
3. 设置 `ADMIN_ORIGIN` 为管理站实际完整来源（如 `https://admin.example.com`），`PUBLIC_GAME_ORIGIN` 为手机和大屏访问的公开来源，`GAME_INTERNAL_ORIGIN` 为后台访问游戏 API 的来源。不带末尾斜杠、路径或用户名密码。
4. 执行 `npm run admin`。默认只监听 `127.0.0.1:5188`，通过独立 HTTPS 管理域名反向代理，并保留原始 Host。玩家域名不要转发到管理端口。代理示例：`proxy_pass http://127.0.0.1:5188; proxy_set_header Host $host;`。
5. 打开管理域名，直接创建比赛；把“打开大屏”用于现场屏幕，玩家只扫描大屏中的 `/play/:code` 二维码。可输入已知房间号继续已有比赛。

## 权限边界

- 游戏服务在创建、开赛、下一局三个操作上检查服务密钥，玩家令牌和旧主持令牌均被拒绝。没有公开创建接口的例外。
- 密钥只用于后台到游戏服务的请求，不放在前端环境变量、URL、网页或浏览器存储中。
- 管理端不再要求密码。任何能访问管理地址的人都能操作比赛；默认只监听本机回环地址，玩家公网域名仍只转发游戏服务。
- 管理写请求仍检查 Host、Origin 和 JSON 内容类型，服务密钥只保留在后端。

## 验证与部署状态

`npm test` 包含实际 HTTP 管理服务测试：免密码直接操作、跨站拒绝、服务密钥不回传、管理转发和参数校验。游戏服务测试验证玩家令牌、旧主持凭证无法管理比赛。

这些是本地代码与 HTTP 测试。尚未部署到用户服务器；原服务器 SSH 握手断开的问题仍需解决。游戏运行时和 D1 的自有服务器适配也仍需完成，不能仅启动管理进程就视为整套公网部署完成。此前 200 人压测针对拆分前版本，本次未重复容量验收。

## 每局排名记录

后台“每局排名记录”可选择局数，查看全部参赛者的排名、昵称、距离和有效摇动次数。开赛时通过数据库触发器保存本局参赛名单和时间；成绩继续保存在 scores 中，比赛结束 2.2 秒后开放最终历史查询。下一局加入的选手不会混入上一局，零分选手和并列排名均保留。管理端重启或刷新不会清空记录，输入原房间号可继续查看。

升级时必须应用 `drizzle/0002_round_history.sql`。迁移会补存仍保有开赛时间的当前局；升级前已经切换走的旧局没有完整时间和名单，无法还原成完整历史记录，不应当作已归档。
