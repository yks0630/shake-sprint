# 一起摇 · 40 秒运动会

现场热场游戏。观众微信扫码、输入昵称参与；主持人统一开赛；比赛期间大屏只展示实时排行榜；比赛结束后展示领奖台和所有参赛者。

## 当前结果

- 人数随加入情况动态变化，没有写死 100 人上限。
- 大屏与手机使用统一开赛时间，3 秒准备倒数后再进行完整 40 秒比赛；每次有效摇动前进 2 米。
- 排名相同距离并列。结算阶段有 2 秒成绩上传缓冲，手机本地计数仍在 40 秒到时停止。
- 主持人可在同一房间开启下一局，保留名单、清零本局分数。
- 手机准备状态通过后端同步：大屏显示加入/准备人数与逐人状态；前台每 2.5 秒上报，停止上报 10 秒后自动过期，刷新后须重新开启。下一局仍开启的手机重新上报。
- 正式比赛数据由后端 D1 数据库同步；不依赖浏览器之间共享本地存储。
- 主持人和选手各持独立随机凭证。公开排行榜不包含凭证。
- 演示预览完全独立，模拟选手不进入正式比赛。
- 人物、动作帧、天空、山丘、旗帜及跑道均使用网上现成素材，详见 ASSETS.md。UI 参考见 DESIGN.md。

## 启动完整项目

需要 Node.js 22.13 或以上。以下命令在项目目录运行。

```bash
npm run install:ci
npm run build
```

首次启动时依次执行下面两条本机数据库迁移。已有数据库已执行过 0000 时，只需执行一次新增的 0001；已经执行过的迁移不要重复执行：

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_burly_emma_frost.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_slippery_scorpion.sql
```

启动：

```bash
npm run dev -- --port 5187
```

访问 `http://localhost:5187`。首页创建比赛后，主持人页面会生成入场二维码，并可单独打开纯大屏页面。

- `/host/房间号`：主持人控制台，在创建比赛的设备上使用。
- `/screen/房间号`：纯大屏，比赛时显示排行榜。
- `/play/房间号`：手机扫码进入，输入昵称并开启摇一摇。
- `/demo`：独立效果演示。
- `/review`：六页界面总览，使用示例数据，可查看昵称入场和三秒开赛状态。

手机要实际使用运动传感器，需要可访问的 HTTPS 地址。局域网 HTTP 地址只能用于一般页面调试，不能代表微信摇一摇已验证。iOS 在“开启摇一摇”时申请动作权限；其他设备先检测是否支持该 API。保持比赛页面在前台。

## 准备状态同步

2026-11-10 已完成。大屏显示“已加入 / 已准备”及逐人准备标记。手机只有开启摇一摇、保持页面在前台并成功上报，才会被服务器计为准备完成；等待服务器确认时显示“准备同步中”，失败会自动重试。

关闭页面或断线后，最后一次上报在 10 秒后过期，叠加大屏约 800 ms 的轮询刷新时间。刷新后需重新开启；下一局不继承旧局准备记录，仍开启的手机会重新上报。准备状态供主持人参考，开赛仍由主持人决定，不强制等待所有人。

真实 HTTP 验证可运行 `node tests/http-readiness.mjs`，需先启动本地服务。接口验证不代替微信物理传感器和现场网络验收。功能尚未发布到公网。
